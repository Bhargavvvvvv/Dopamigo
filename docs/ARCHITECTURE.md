# Architecture

Modular Electron monolith. One Gemini planning agent with a small tool registry; speech is a separate provider, not a second agent. Session state, permission gates, timers, cooldowns, suppression, and persistence are deterministic.

| Boundary | Location | Responsibility |
| --- | --- | --- |
| Shared contracts | `packages/contracts` | Zod models, IPC inputs, extension protocol, typed bridge |
| Domain/application | `packages/core` | Canonical state, serialized store, repository interface, session transitions, checkpoints, staged drafts, planning tools, nudge rules, demo |
| Privileged adapters | `apps/desktop/main/adapters` | Atomic JSON repository, Gemini planning/nudge writing, Google TTS, authenticated browser server |
| Orchestration | `apps/desktop/main` | IPC use cases, nudge/audio cancellation, lifecycle, tray, launcher |
| UI | `apps/desktop/renderer` | Plan/Work/Return/Settings, media playback, non-focusable nudge view |
| Google integration | `apps/desktop/main/google` + `packages/core/assignments` | PKCE login, encrypted refresh credentials, read-only Calendar/Drive clients, Gemini classification, serialized sync and local task reconciliation |
| Chrome | `apps/browser-extension` | Active-domain signals, saved/pinned work-tab tracking and restoration |

`AppState` is the single durable state: version, revision, projects/plans/steps, selected project, session, checkpoints, preferences. The main-process store serializes mutations; it publishes typed snapshots only after a successful atomic save. Draft notes are staged in memory and debounced 450 ms, then checkpointed. Actions, view navigation, window close, and quit flush them; concurrent flushes wait for pending saves before returning a snapshot. Restart, system sleep, and screen lock pause active sessions. Validated backups recover interrupted writes; unknown schema versions fail closed and preserve the original files.

Planning calls Google `generateContent` with `submit_plan` and (at most once) `ask_clarification`. The registry validates model arguments; tools propose plans and the application owns writes. No arbitrary execution or browser tools are available to the model. Add tools/providers here without changing the shell or session state machine. Mock output always carries `source: mock` and is labelled in the UI.

Each eligible detour calls the Gemini nudge-writer adapter with the current hostname, task, step, next action, style and the last three generated lines. It makes one bounded structured-output request (15-second timeout, 280 characters/50 words maximum), validates the result, then passes exactly that text to the separate TTS provider. No static phrase bank or spoken fallback exists. Recent lines stay in session memory to discourage repetition. A single cancellation token spans writing and synthesis; site/work/style changes, pauses and dismissal discard stale results. The card shows the saved next action while writing or on failure, with return controls always available. Voice preview follows the same generation path. No page title, video, comments or feed contents are inspected. Dwell/cooldown rules remain deterministic; nudge writing is a single completion, not another autonomous agent.

Google TTS uses the documented Interactions REST audio response for the current default model, with a configurable legacy `generateContent` adapter for older model IDs. WAV/PCM is validated. An in-memory cache holds at most 12 clips. Context changes (including switching sites) abort pending speech and stop renderer playback. Voice failure leaves the visual nudge operational. The renderer receives audio and status, never provider credentials.

Chrome uses a loopback-only WebSocket with extension-origin checks, random 256-bit pairing token, authentication timeout, schema validation, payload and rate limits, and heartbeat liveness. Signals and work-tab IDs are ephemeral. The extension queries the active URL only while enabled, sends the hostname/IDs/relevance flag, and never sends bodies, full browsing URLs, or history. Chrome permissions still grant technical access to tab metadata; the opt-in gate is enforced in extension and desktop code. Saved resource URLs travel locally to match work tabs.

Electron uses context isolation, sandboxed preload, Node integration disabled, sender/frame checks, denied remote navigation/new windows, and denied unused permission requests. Main/nudge/launcher renderers use a narrow typed bridge. Production CSP excludes inline scripts; Vite development adds a per-run nonce. Packaged builds ignore development-server URLs. Only validated HTTP(S) saved links can reach `shell.openExternal`.

Google sync runs on launch, wake and a ten-minute timer in the main process. Calendar events are classified in bounded Gemini batches, with cached results for unchanged events. Stable account/event keys deduplicate imports, and tracked events are fetched even when moved outside the two-week window. Reconciliation only updates imported metadata/resources and adds starter workspaces; it preserves notes, plans and sessions. Drive metadata matching is local. Existing version-1 state loads with Google disconnected by default; credentials live in a separate encrypted file. Local PDF/TXT/Markdown briefs use a file dialog and bounded extraction, with `unpdf` externalized into the packaged runtime. See [GOOGLE.md](GOOGLE.md) for permissions and limits.

Build: Vite renderer + esbuild main/preload; electron-builder produces the current architecture’s `.app`. No Dopamigo cloud sync, telemetry, general plugin framework, or arbitrary app-content capture. Google OAuth is optional.
